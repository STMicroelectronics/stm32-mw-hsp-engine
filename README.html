Middleware HSP Engine Component

Overview

The HSP Engine middleware provides an efficient interface to the Hardware Signal Processor (HSP) available on some STM32 microcontrollers. The HSP peripheral accelerates or offloads signal processing operations commonly used in applications such as signal conditioning, metering, anomaly detection and speech recognition. It can also support control-loop applications for motor control and digital power.

The HSP is built around a dedicated Signal Processor Engine (SPE) able to operate in 32-bit floating point or 8-bit integer modes. The SPE executes HSP-specific microcode (firmware): one part is embedded in a private ROM, the other part (FW RAM) is loaded into RAM at initialization.

Main features

  • Accelerator mode: immediate execution of a single processing function through the HSP Direct Command interface. The processing functions are provided by three libraries:
    • Direct library: math functions (similar to the C math library).
    • DSP library: subset of processing functions using the same prototypes as the Arm CMSIS-DSP library.
    • CNN library: Convolutional Neural Network processing functions.
  • Sequencer mode: execution of a sequence of processing functions, called a Processing List, programmed with the HSP Sequencer. A Processing List can be triggered by the CPU or by hardware events (such as a DMA transfer-complete event), and is executed without CPU intervention. The Processing List APIs are organized into the following categories:
    • Complex
    • Conditional (if-then-else and loops)
    • Digital control
    • Filter (FIR, IIR, …)
    • Matrix
    • Scalar (scalar and conversion functions)
    • Transform (FFT and DCT)
    • Vector
  • Core services: initialization, output trigger (TRGO), smart clocking and protection.
  • BRAM management: allocation of resources in the HSP BRAMAB memory region.
  • Monitoring services: performance monitor and timestamp capture.
  • Optimized memory copy (HSP_MEMCPY) with assembly implementations for GCC, IAR and Arm toolchains.
  • Support of STM32CubeMX2 configuration and code generation.

Folder structure

Folder Description
common/core HSP Engine core services (initialization, configuration) and BRAM manager.
common/modules Direct, DSP, CNN and Processing List libraries, and the HSP firmware binaries (firmware/).
common/monitoring Services to monitor the HSP.
common/proclist Services to record and manage Processing Lists.
common/utilities HSP Engine utilities (optimized memory copy, …).
interfaces Low-level interfaces to manage the HSP BRAM allocation (hsp_bram_if) and to drive the HSP peripheral through the HSP HAL driver (hsp_hw_if).
templates Application and interface templates (hsp_conf.h, hsp_engine_rsrc_map.h, mx_hsp_engine_app.*, …) to copy and adapt in the application project.

Supported devices and firmware

The HSP firmware ROM version depends on the device series. The firmware RAM binaries are provided under common/modules/firmware/ (crom_x_y_z/cram_xx_yy) and are selected according to the device series.

Low-level drivers

The HSP Engine relies on the STM32 HAL2 HSP driver. The interfaces folder provides ready-to-use implementations that can be adapted to replace the default BRAM management or to connect the HSP Engine to a custom HSP driver.

Configuration

The HSP Engine is configured at application level through:

  • hsp_conf.h: selection of the libraries and features (USE_HSP_MODULES_*, USE_HSP_ENGINE_*, timeouts, BRAM size reserved for CNN, …).
  • hsp_engine_rsrc_map.h: aliases between the application and the HAL driver literals.

Both files are generated by STM32CubeMX2, or can be created manually starting from the provided templates.

Getting started

  • With STM32CubeMX2: enable the HSP peripheral, add the HSP Engine middleware, then select the Accelerator mode libraries and the HSP peripheral instance in the HSP Engine panels. STM32CubeMX2 generates hsp_conf.h, hsp_engine_rsrc_map.h, mx_hsp_engine_app.c and mx_hsp_engine_app.h.
  • Without STM32CubeMX2: add the sources of common/core, the selected common/modules libraries, the firmware matching the device series and the interfaces folder to the project. Add the corresponding include paths, provide a single hsp_conf.h and a single hsp_engine_rsrc_map.h, include hsp.h in the application, and call HSP_CORE_Init() before using any service.
